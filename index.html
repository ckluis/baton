baton 8.0.0 · 2026-11-11

Just a usage line.

baton started as a team of agents for Claude Code. Eight versions in under three months later, the part worth keeping fits on one line: how much of your plan is left, right above the prompt.

> ▌
5h ▕░░░░░▏ 7% resets 14:30 EST · fable ▕██░░░▏ 31% · wk ▕███░░▏ 52% resets Mon 07:00 EST · ctx ▕░░░░░▏ 5%

Runs on macOS, Linux and Windows with what they already have: no Node, no plugin. Green, then yellow from 60%, red from 85%. Times are in your own time zone. On a narrow window the line drops bars first, then reset times, then Fable, then weekly.

What it shows

Four numbers. When one isn't known yet, it says n/a and why, never a guess.

5h

Your 5-hour limit, and the time it resets.

From the status line JSON: rate_limits.five_hour

fable

Your separate weekly Fable limit.

From Claude Code's usage request, checked in the background every 5 minutes. No tokens.

wk

Your weekly limit, and the day and time it resets.

From the status line JSON: rate_limits.seven_day

ctx

How full this chat's context is.

From the status line JSON: context_window.used_percentage

Install

One small script, no plugin, nothing to build. Needs Claude Code 2.1.80 or later.

macOS · Linux · WSL

Needs sh, date and jq. macOS 15+ has them all; on Linux, apt install jq.

curl -fsSL -o ~/.claude/baton-usage-line.sh \
  https://raw.githubusercontent.com/ckluis/baton/main/statusline/usage-line.sh

Then in ~/.claude/settings.json:

"statusLine": {
  "type": "command",
  "command": "sh ~/.claude/baton-usage-line.sh",
  "refreshInterval": 60
}

Windows

Needs nothing extra: the PowerShell every Windows has.

Invoke-WebRequest -UseBasicParsing `
  -OutFile "$HOME\.claude\baton-usage-line.ps1" `
  https://raw.githubusercontent.com/ckluis/baton/main/statusline/usage-line.ps1

Then in settings.json (forward slashes):

"statusLine": {
  "type": "command",
  "command": "powershell -NoProfile -ExecutionPolicy Bypass -File C:/Users/YOU/.claude/baton-usage-line.ps1",
  "refreshInterval": 60
}

Start a new session and the line is there. Coming from baton v7? First run claude plugin uninstall baton@baton.

How baton got here

Every version tried to fix a real problem. Most of the fixes were later measured, found unnecessary, or built into Claude Code itself. Here is each one: what it was for, and why it went.

v12026-08-23

The conductor never plays a note

WhyOne chat doing a big job runs out of room and grades its own work. v1 was a single 571-line prompt: a lead that only hands out work, helpers that do it, notes passed on disk, a four-tier model ladder, and a separate checker trying to prove each result wrong.

Dropped: it worked, but it ran the most expensive model for everything.

The v1 page

v22026-08-24

The cheapest agent that can succeed

WhyCut the cost. Six levels of model and effort, starting cheap and climbing only when a check failed.

Dropped: later tests showed the ladder barely changed results. With stronger models the big model was no longer the expensive part.

The v2 page

v32026-08-31 → 09-17

Named experts and new modes

WhyBetter reviews: 40 named-expert reviewer personas, new modes, and rules learned by running baton on itself.

Dropped: in v7's own test, the expert panel did no better than one plain reviewer.

The v3 page

v42026-09-18

For you or a team

WhyLet a team share a run: git as the record, pull requests for the changes, issues for the questions a person has to answer.

Dropped: it lived on as v7.1's GitHub goals and went away with the mod.

The v4 page

v52026-09-21

Agents do the work, baton keeps the record

WhyWith much smarter models, the rules about which model to use stopped mattering. v5 kept only the checking: evidence that cites or takes it back, per-item verdicts, and gates a person holds.

Dropped: the checking carried on through v6 and v7 and went away with the mod. The habit stays.

The v5 page

v62026-10-02

The shrink

WhySix experiments on Opus 5.5 and Sonnet 5.5 found that model, effort and persona choices moved results by fractions of a point. What really failed: goals no check could settle, a broken environment, and claims nobody checked. v6 cut about 30% of baton.

Dropped: the lesson stuck, and the next version shrank further.

The v6 page The experiments

v72026-10-05 → 10-19

The mod

WhyRebuilt inside Claude Code's mod system: a guarded lead that only hands out work, a memory instead of a growing chat, Work and Memory views, a command gate, GitHub goals, per-agent cost meters, and a usage strip. Before building it, v7 tested whether long chats get worse (no: 24/24 out to 831K tokens and 29 compactions) and whether the expert panel helped (no).

Dropped: the mod system changed under baton more than once, and keeping up became the main job.

v7.5.1 code v7 design The v8 plan that never shipped

v7.6demo 2026-11-11

Tuned for the Claude Code you run

Whyv7.5.1 found four bugs in one afternoon of real use that the tests had missed. v7.6 checked every part against the live Claude Code.

Dropped: in the live demo the goal was met, but two tiny files took $4.78 and 1 h 36 m. Opening a view took three keys, the table columns didn't line up, times mixed UTC and local, and baton refused to write its own final report.

The v7.6 pull request

v82026-11-11

Just a usage line

WhyThe part still worth having was the usage numbers. Claude Code's status line now gets the 5-hour, weekly and context numbers directly, and its usage request has Fable. A shell script on macOS and Linux and a PowerShell script on Windows draw it, with no Node and no plugin.

Kept: one small script, one line. Use Claude Code the way Anthropic built it.

Changelog The code

Why most of it went away

baton was always a bet that Claude Code needed scaffolding around it. Each version's own experiments chipped at that bet:

  • The model ladder (v2) priced a world where the big model was the expensive part. That world went away.
  • Expert personas (v3) scored the same as one plain reviewer.
  • Long chats didn't get worse on Opus 5.5, so a memory that replaced the chat (v7) fixed a problem that wasn't there.
  • Claude Code has its own pieces now: subagents, workflows, a usage screen, rate limits in the status line. Its mod system changed fast enough that keeping up became the main job.

The checking ideas held up: evidence over claims, a fresh look at finished work, a person holding the gate. They're habits now, not code. What's left in the repo is the line at the top of this page.
