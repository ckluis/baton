11Files first

Works before you install anything.

The memory, rulings, templates and preflight are plain files. Any agent can read them and any Workflow script can use them. The mod is the accelerator: it watches, keeps the files current, draws the pane and nudges. If the mod can't load (mods are still early access), nothing breaks; you just lose the live view.

Files no install · any harness

MEMORY.md as the root catalog · user / project / tech / tool catalogs and their nodes · rulings.md imported by CLAUDE.md · the unit-loop template and agent types with pinned model IDs · env checks · the session node

Mod Claude Code plugin

Watch pane and live change feed · served-model flags and models enforce · the Haiku 5.5 curator that folds notes into nodes · ruling extraction · close/resume commands · meter + nudge · the guard that keeps MEMORY.md a root

Claude Workflows the engine

Deterministic phases, schemas, concurrency, resume from the journal. baton never replaces it. It watches it, feeds it knowledge and remembers what it did.

What still needs proving

v8 is a design. These are the first things a spike must settle before any of it ships:

  1. Is the mods rollout on? On 2026-10-04 it was "served off", and v7's plugin tests have never run live.
  2. Can Workflow agents call the mod's memory tools? If not, they read the catalog files directly, which still works.
  3. Does a CLAUDE.md import written mid-session reach agents that start later? This decides how fresh rulings are.
  4. Is the requested model visible at spawn, before alias resolution? This decides whether models enforce can catch haiku → 4.5.
  5. Is wf_*.json stable? It's an internal format, so the reader must fail loudly ("format changed") rather than draw blanks.

Build order

  1. Model truth: prices, full IDs, served model on every row
  2. Memory graph format, tools and the curator
  3. Migrate the existing memory: copy, A/B on 10 real openers, swap, archive
  4. Project catalog: session + env
  5. Watch pane + change feed
  6. Rulings to every agent + templates + merge queue
  7. UI-check drivers, then the Haiku tier experiment

12Install

Two lines, when it ships.

v8 is a design preview. Today's release is v7.5. When v8 lands, this is the whole setup.

The mod

# once, in Claude Code
/plugin marketplace add ckluis/baton
/plugin install baton@baton
# then just work: the pane opens when a Workflow starts
/baton doctor

Doctor checks the Claude Code version, what each model alias resolves to, the UI-check drivers it finds, and whether mods can load.

Files only

# no plugin: build the catalogs from your memory
baton mem init         # root + user + this project
baton mem migrate --copy --ab 10
baton mem doctor       # orphans, stale nodes, broken links

Planned CLI. Every command writes plain Markdown you can read and diff.
